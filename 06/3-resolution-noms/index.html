    42. VI.3 Résolution de noms côté client

    En pratique, les utilisateurs et les applications (comme un client Java qui se connecte à bdd-prod.entreprise.local) manipulent des noms symboliques plutôt que des adresses IP numériques. La résolution de noms assure la traduction entre ces noms d'hôtes et les adresses IP.

    Cette section détaille les quatre fichiers de configuration côté client et les outils d'interrogation DNS couverts par l'objectif LPIC-1 109.4.

    42.1 VI.3.1 Les fichiers de configuration client

    42.1.1 VI.3.1.1 Le fichier /etc/hosts (Résolution statique locale)

    Le fichier /etc/hosts associe manuellement des adresses IP à un ou plusieurs noms d'hôtes (nom complet FQDN et alias courts). Il fonctionne sans serveur DNS et reste indispensable pour résoudre localhost ou pallier une panne DNS en urgence :

    127.0.0.1       localhost
172.16.12.2     rodent.wrotethebook.com rodent
172.16.12.1     crab.wrotethebook.com crab loghost
10.20.30.40     db-prod.interne db-prod

    42.1.2 VI.3.1.2 Le fichier /etc/networks (Noms de réseaux)

    De manière analogue à /etc/hosts, le fichier /etc/networks associe des noms lisibles à des adresses de réseaux entiers (utilisé par certaines commandes comme route sans option -n) :

    loopback        127.0.0.0
mylan           192.168.1.0

    Impact sur la commande route : sans l'option -n (numeric), route traduit l'adresse 192.168.1.0 en mylan à l'affichage (et vous pouvez également utiliser le nom mylan lors d'un route add -net mylan ...) :

    // Sans -n : résolution via /etc/networks (affiche "mylan")
$ route
Table de routage IP du noyau
Destination     Passerelle      Genmask         Indic Metric Ref    Use Iface
default         192.168.1.1     0.0.0.0         UG    100    0        0 ens33
mylan           0.0.0.0         255.255.255.0   U     100    0        0 ens33

// Avec -n : affichage numérique brut (ignore /etc/networks et DNS)
$ route -n
Table de routage IP du noyau
Destination     Passerelle      Genmask         Indic Metric Ref    Use Iface
0.0.0.0         192.168.1.1     0.0.0.0         UG    100    0        0 ens33
192.168.1.0     0.0.0.0         255.255.255.0   U     100    0        0 ens33

    42.1.3 VI.3.1.3 Le fichier /etc/resolv.conf (Serveurs DNS du client)

    Ce fichier indique à la bibliothèque de résolution (resolver) les adresses IP des serveurs DNS à interroger, dans l'ordre d'apparition (jusqu'à 3 directives nameserver), ainsi que les domaines de recherche par défaut :

    search entreprise.local prod.local
nameserver 192.168.1.5
nameserver 192.168.250.2
    • nameserver : IP du serveur DNS récursif. Si le premier répond, les suivants ne sont pas interrogés ; s'il ne répond pas (timeout), le client bascule sur le suivant.
    • search : liste de suffixes ajoutés automatiquement si l'utilisateur tape un nom court (ex. ping db-prod cherchera db-prod.entreprise.local).

    /etc/resolv.conf géré dynamiquement

    Sur les distributions modernes utilisant NetworkManager ou systemd-resolved, /etc/resolv.conf est souvent un lien symbolique ou un fichier généré automatiquement à chaque renouvellement DHCP. Une modification manuelle directe risque d'être écrasée au redémarrage du réseau.

    42.1.4 VI.3.1.4 Le fichier /etc/nsswitch.conf (Ordre des sources de résolution)

    Le fichier /etc/nsswitch.conf (Name Service Switch) définit l'ordre de priorité dans lequel le système consulte ses différentes bases d'information (utilisateurs, groupes, hôtes).

    La ligne hosts: contrôle la résolution des noms de machines :

    hosts:          files dns nisplus nis

    Ordre d'exécution :

    1. files : consulte d'abord le fichier local /etc/hosts.
    2. dns : si le nom n'y figure pas, interroge les serveurs DNS listés dans /etc/resolv.conf.
    3. nisplus / nis : interroge d'éventuels annuaires NIS si configurés.
    flowchart LR
    App["Application / ping db-prod"] --> NSS["/etc/nsswitch.conf<br/>(hosts: files dns)"]
    NSS -->|1. files| Hosts["/etc/hosts"]
    Hosts -->|Trouvé| IP["Adresse IP retournée"]
    Hosts -->|Absent| DNS["2. dns -> /etc/resolv.conf<br/>(nameserver 192.168.1.5)"]
    DNS --> IP

    42.2 VI.3.2 Outils de diagnostic de la résolution de noms

    42.2.1 VI.3.2.1 host : interrogation DNS simple

    La commande host effectue rapidement une résolution directe (nom → IP) ou inverse (IP → nom) :

    // Résolution directe
$ host uberpc
uberpc has address 192.168.1.76

// Résolution inverse (enregistrement PTR)
$ host 192.168.1.76
76.1.168.192.in-addr.arpa domain name pointer uberpc.local.

    42.2.2 VI.3.2.2 dig : diagnostic DNS détaillé

    dig (Domain Information Groper) est l'outil de référence pour analyser en profondeur la réponse d'un serveur DNS (statut NOERROR/NXDOMAIN, type d'enregistrement A, AAAA, MX, NS, serveur interrogé et temps de réponse) :

    $ dig uberpc

; <<>> DiG 9.18.18 <<>> uberpc
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 48211
;; flags: qr aa rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; QUESTION SECTION:
;uberpc.                        IN      A

;; ANSWER SECTION:
uberpc.                 0       IN      A       192.168.1.76

;; Query time: 2 msec
;; SERVER: 192.168.1.5#53(192.168.1.5)

    Usages courants de dig :

    // Interroger un serveur DNS spécifique (ex. Google 8.8.8.8)
$ dig @8.8.8.8 lpi.org

// Afficher uniquement l'adresse IP résultante
$ dig +short lpi.org

// Interroger les serveurs de messagerie (MX)
$ dig MX lpi.org

    42.2.3 VI.3.2.3 getent : tester la résolution réelle du système

    Piège classique : dig ignore /etc/hosts !

    Les commandes dig, host et nslookup interrogent exclusivement les serveurs DNS et ignorent totalement /etc/hosts et /etc/nsswitch.conf.
    Pour vérifier ce que voit réellement une application (Java, Python, curl, ping) en respectant l'ordre de /etc/nsswitch.conf, utilisez getent hosts :

    $ getent hosts db-prod
10.20.30.40     db-prod.interne db-prod
