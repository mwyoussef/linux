    33. V.4 Gestion de la mémoire d'échange (Swap)

    La mémoire vive (RAM) est une ressource rapide mais limitée et volatile. Sous Linux, l'espace d'échange (Swap) sert de tampon d'extension sur le disque physique pour seconder la RAM.

    Cette section examine le fonctionnement du Swap, les règles de dimensionnement modernes, ainsi que les deux méthodes de mise en œuvre (partition dédiée et fichier swap) requises pour la certification LPIC-1 (Objectifs 102.1 et 104.1).

    33.1 V.4.1 Rôle et fonctionnement de l'espace Swap

    L'espace Swap remplit trois fonctions capitales dans la gestion de la mémoire sous Linux :

    Débordement de la mémoire vive (Memory Overflow)

    Lorsque les applications réclament plus de mémoire physique que la quantité de RAM réellement installée, le noyau déplace les blocs de mémoire les moins récemment utilisés (pages anonymes) vers le disque dur afin d'éviter le blocage immédiat des processus.

    Attention au thrashing (emballement du disque)

    La vitesse d'accès au disque (même sur un SSD NVMe ultra-rapide) reste des centaines de fois plus lente que les débits de la RAM (nanosecondes vs microsecondes). Si la RAM est totalement saturée et que le système passe son temps à échanger des pages entre la RAM et le swap, la machine ralentit drastiquement : ce phénomène est appelé thrashing.

    Optimisation du cache disque (Page Cache)

    Contrairement à une idée reçue, le Swap n'est pas uniquement utilisé lorsque la RAM est saturée à 100 %. Le noyau déplace volontairement certaines pages de programmes endormies ou inactives vers le Swap, afin de libérer de la mémoire vive rapide au profit du cache de fichiers (page cache), ce qui accélère les entrées/sorties globales du système.

    Veille prolongée et hibernation (Suspend-to-Disk)

    Lors d'une mise en veille prolongée (notamment sur les ordinateurs portables), le noyau copie l'intégralité du contenu de la mémoire vive dans l'espace Swap avant de couper l'alimentation électrique de la carte mère. Au redémarrage suivant, la RAM est restaurée depuis le Swap.

    Qu'arrive-t-il si la RAM et le Swap sont pleins ?

    Si la mémoire vive et le Swap sont tous deux saturés, le mécanisme d'urgence du noyau appelé OOM Killer (Out-Of-Memory Killer) se déclenche : il analyse les processus en cours et en tue immédiatement un ou plusieurs arbitrairement (souvent le processus le plus gourmand) avec un signal SIGKILL pour préserver le noyau.

    33.2 V.4.2 Règles de dimensionnement recommandées

    Historiquement, une règle empirique prescrivait de créer un Swap équivalent au double de la mémoire vive. Cette règle date de l'époque où les ordinateurs ne possédaient que 128 Mo à 512 Mo de RAM.

    Sur les serveurs actuels équipés de 32 Go, 64 Gio ou 512 Go de RAM, allouer le double serait un gaspillage considérable de stockage.

    Mémoire RAM installée Swap recommandé (sans hibernation) Swap avec hibernation
    Moins de 2 Gio 2 x taille RAM 3 x taille RAM
    De 2 Gio à 8 Gio Égale à la RAM (ex. 4 Gio) 2 x taille RAM
    De 8 Gio à 64 Gio 4 Gio à 8 Gio Taille de la RAM + 2 Gio
    Plus de 64 Gio 4 Gio à 16 Gio Non recommandé (hibernation trop lente)

    33.3 V.4.3 Création Swap et activation

    33.3.1 V.4.3.1 Méthode 1 : Créer une partition Swap dédiée

    C'est la méthode classique lors du partitionnement initial d'un disque.

    • Étape 1 : Affecter le code de type Swap

      Lors de la création de la partition avec fdisk ou gdisk :

      • Avec fdisk (MBR) : utilisez la commande t, puis renseignez le code hexadécimal 82 (Linux swap / Solaris).
      • Avec gdisk (GPT) : utilisez la commande t, puis renseignez le code hexadécimal 8200 (Linux swap).

    • Étape 2 : Initialiser la signature Swap (mkswap)

      La commande mkswap prépare la partition en y écrivant la signature spécifique de la mémoire d'échange :

      $ sudo mkswap /dev/sdb2
Setting up swapspace version 1, size = 4 GiB (4294963200 bytes)
no label, UUID=a47b85e1-5c31-419b-98df-892cb3489e21

      Vous pouvez également lui attribuer un label avec l'option -L :

      $ sudo mkswap -L SWAP_DISK /dev/sdb2

    • Étape 3 : Activer la partition Swap (swapon)

      Pour rendre la partition immédiatement utilisable par le noyau :

      $ sudo swapon /dev/sdb2

    33.3.2 V.4.3.2 Méthode 2 : Créer un fichier Swap (Swap File)

    Sur un serveur en production dont le partitionnement est figé, il est courant de manquer d'espace Swap. Créer un fichier d'échange (swapfile) permet d'ajouter du Swap dynamiquement en quelques secondes, sans aucun repartitionnement ni redémarrage.

    • Étape 1 : Allouer un fichier contigu de 2 Gio à la racine

      $ sudo fallocate -l 2G /swapfile

    • Étape 1 alternative : Utiliser la commande dd si fallocate n'est pas supporté par le FS :

      // sudo dd if=/dev/zero of=/swapfile bs=1M count=2048 status=progress

      La règle de sécurité impérative : permissions 600

      Le fichier Swap contiendra des fragments bruts de mémoire vive, incluant potentiellement des mots de passe en clair, des clés privées SSH ou des jetons d'authentification.

      Il est absolument obligatoire de restreindre l'accès en lecture et écriture au seul utilisateur root :

      $ sudo chmod 600 /swapfile
$ ls -l /swapfile
-rw------- 1 root root 2147483648 nov.  10 11:30 /swapfile

    • Étape 2 : Initialisation du fichier Swap

      $ sudo mkswap /swapfile
Setting up swapspace version 1, size = 2 GiB (2147479552 bytes)
no label, UUID=c82f9d10-8b43-4318-ae71-d41a79f6d4d2

    • Étape 3 : Activation immédiate du fichier Swap

      $ sudo swapon /swapfile

    33.4 V.4.4 Commandes d'administration et surveillance du Swap

    • Synthèse globale avec free -h

      $ free -h
            total        used        free      shared  buff/cache   available
Mem:            15Gi       4,2Gi       6,8Gi       412Mi       4,1Gi        10Gi
Swap:          6,0Gi       512Mi       5,5Gi

    • Détail des espaces actifs avec swapon --show

      $ swapon --show
NAME      TYPE      SIZE  USED PRIO
/dev/sda3 partition   4G  512M   -2
/swapfile file        2G    0B   -3

      La colonne PRIO indique la priorité d'utilisation. Si plusieurs espaces de swap existent, le noyau remplit en premier celui dont la priorité est la plus élevée (le nombre le moins négatif).

    • Consultation directe de /proc/swaps

      Le noyau expose ses espaces de swap montés dans le pseudo-système de fichiers /proc :

      $ cat /proc/swaps
Filename                Type        Size        Used        Priority
/dev/sda3               partition   4194300     524288      -2
/swapfile               file        2097148     0       -3

    • Désactivation d'un espace Swap avec swapoff

      Pour désactiver un swap (par exemple avant de retirer un disque ou de supprimer un fichier) :

      $ sudo swapoff /swapfile

      Vérifiez la RAM libre avant d'exécuter swapoff

      Lorsqu'on désactive un espace de swap avec swapoff, le noyau rapatrie obligatoirement en RAM toutes les pages qui y étaient stockées. S'il n'y a pas assez de RAM disponible, la commande échouera ou déclenchera l'OOM Killer.

    33.5 V.4.5 Configuration permanente dans /etc/fstab

    Pour que vos espaces d'échange soient automatiquement réactivés lors du prochain démarrage de la machine, ils doivent être consignés dans /etc/fstab :

    # Pour une partition Swap (via son UUID) :
UUID=a47b85e1-5c31-419b-98df-892cb3489e21  none  swap  sw  0  0

# Pour un fichier Swap :
/swapfile                                   none  swap  sw  0  0
    • Le point de montage d'un swap est conventionnellement désigné par none ou swap.
    • Le type de système de fichiers est obligatoirement swap.
    • L'option standard est sw (ou defaults).
    • Les deux derniers chiffres de sauvegarde et de vérification (dump et pass) sont toujours 0 0.

    33.6 V.4.6 Réglage du comportement : le paramètre swappiness

    Le paramètre du noyau vm.swappiness (valeur comprise entre 0 et 100) détermine avec quelle agressivité le noyau transfère les pages de la RAM vers le Swap :

    • swappiness = 0 : Évite d'utiliser le swap tant que la RAM n'est pas au bord de la saturation absolue.
    • swappiness = 60 : Valeur par défaut sur la plupart des distributions Linux (bon compromis pour un poste de travail).

    • swappiness = 10 : Réglage courant pour les serveurs de production (notamment les bases de données comme PostgreSQL ou MySQL) pour privilégier au maximum la réactivité de la RAM.

    • Consulter la valeur actuelle

      $ cat /proc/sys/vm/swappiness
60

    • Modifier temporairement à chaud la valeur

      $ sudo sysctl vm.swappiness=10

    • Rendre la modification permanente dans /etc/sysctl.conf

      $ echo "vm.swappiness = 10" | sudo tee -a /etc/sysctl.conf
