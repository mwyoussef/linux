    35. V.6 Montage des systèmes de fichiers et configuration de /etc/fstab

    Sous Linux, il n'existe pas de lettres de lecteurs indépendantes (comme C: ou D: sous Windows). Le système s'articule autour d'une arborescence hiérarchique unifiée débutant à la racine unique /.

    Le montage (mounting) est le processus par lequel un système de fichiers hébergé sur une partition ou un volume logique est rattaché à un répertoire spécifique de cette arborescence, appelé point de montage (mount point).

    Cette section détaille les commandes de manipulation manuelle (mount, umount), les méthodes d'identification fiables (UUID, Label), l'architecture complète du fichier de configuration automatique /etc/fstab et les utilitaires de contrôle, conformément à l'objectif LPIC-1 104.3.

    35.1 V.6.1 Le montage manuel avec la commande mount

    La syntaxe canonique de la commande mount associe un périphérique source à un répertoire cible :

    $ sudo mount <périphérique> <point_de_montage>

    Par exemple, pour monter la partition /dev/sdb1 dans le répertoire /mnt/data :

    // 1. Création préalable du point de montage (s'il n'existe pas)
$ sudo mkdir -p /mnt/data

// 2. Montage de la partition
$ sudo mount /dev/sdb1 /mnt/data

    Attention aux dossiers non vides

    Le point de montage doit idéalement être un répertoire vide. Si vous montez un périphérique sur un répertoire contenant déjà des fichiers, ces derniers ne sont pas supprimés, mais ils deviennent totalement invisibles et inaccessibles tant que le périphérique reste monté.

    35.1.1 V.6.1.1 Options fréquentes de la commande mount

    Option Description Exemple
    -t <type> Spécifie explicitement le type de FS (ext4, xfs, vfat, iso9660). En son absence, le noyau tente une autodétection. mount -t ext4 /dev/sdb1 /mnt/data
    -o <options> Passe une liste d'options de montage séparées par des virgules. mount -o ro,noexec /dev/sdb1 /mnt/data
    -o remount Modifie les options d'un système de fichiers déjà monté sans le démonter. mount -o remount,rw /
    -o loop Monte une image disque brute ou un fichier ISO comme un périphérique bloc. mount -o loop debian.iso /mnt/iso
    -a Tente de monter tous les systèmes de fichiers déclarés dans /etc/fstab. sudo mount -a

    35.2 V.6.2 Le démontage avec umount

    Pour détacher proprement un système de fichiers, on utilise la commande umount (attention à l'orthographe : il n'y a pas de lettre « n » après le « u » !).

    On peut indifféremment spécifier le point de montage ou le périphérique :

    $ sudo umount /mnt/data
// ou :
$ sudo umount /dev/sdb1

    35.2.1 V.6.2.1 Le piège classique : target is busy

    Lors d'une tentative de démontage, Linux refuse fréquemment l'opération avec le message d'erreur :

    umount: /mnt/data: target is busy.

    Cette protection empêche la corruption des données lorsqu'au moins un processus utilise la partition :

    • Un terminal d'un utilisateur a pour répertoire courant /mnt/data (ou l'un de ses sous-dossiers).
    • Un démon système maintient un fichier ouvert en lecture ou écriture.
    // Identifier les processus bloquants avec lsof
$ sudo lsof +f -- /mnt/data
COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
bash    14208 wassim  cwd    DIR   8,17     4096    2 /mnt/data

// Ou avec la commande fuser
$ sudo fuser -vm /mnt/data

    Une fois que l'utilisateur a quitté le dossier (cd ~) ou que le processus est arrêté, le démontage réussit.

    En cas d'urgence sur un support réseau ou un disque inaccessible, le démontage différé (lazy unmount) avec l'option -l détache immédiatement le système de fichiers de l'arborescence et libère les ressources dès que les accès en cours s'achèvent :

    $ sudo umount -l /mnt/data

    35.3 V.6.3 Identification des périphériques : Device, UUID et LABEL

    Dans les scripts et la configuration système, un volume peut être désigné de trois manières :

    35.3.1 V.6.3.1 Identification par le chemin matériel (/dev/sda1, /dev/sdb1)

    Cette méthode est fortement déconseillée pour les montages permanents. L'attribution des lettres sda, sdb est dynamique : si un disque dur est déplacé sur un autre port de la carte mère ou si un câble USB est branché au démarrage, l'ordre peut s'inverser et corrompre le démarrage de la machine.

    35.3.2 V.6.3.2 Identification par UUID (Universally Unique Identifier)

    C'est la méthode de référence absolue recommandée par toutes les distributions modernes. L'UUID est un identifiant unique universel de 128 bits attribué au moment du formatage :

    $ sudo blkid /dev/sdb1
/dev/sdb1: UUID="98a3b547-7592-4fcf-bc08-41584cb02ff0" BLOCK_SIZE="4096" TYPE="ext4"

    Dans les commandes et configurations, on l'utilise sous la forme : UUID=98a3b547-7592-4fcf-bc08-41584cb02ff0

    35.3.3 V.6.3.3 Identification par LABEL (Étiquette de volume)

    Permet de désigner un volume par un nom convivial et intelligible pour l'administrateur :

    // Définir un label sur une partition ext4 existante
$ sudo e2label /dev/sdb1 SAUVEGARDES

// Définir un label sur une partition XFS
$ sudo xfs_admin -L DONNEES /dev/sdb2

    Dans /etc/fstab, on l'utilise sous la forme : LABEL=SAUVEGARDES

    35.4 V.6.4 Configuration permanente : Le fichier /etc/fstab

    Le fichier texte /etc/fstab (File Systems Table) répertorie tous les périphériques de stockage qui doivent être montés automatiquement lors de l'initialisation du système.

    Chaque ligne de /etc/fstab comprend rigoureusement 6 colonnes, délimitées par des espaces ou des tabulations :

    # <périphérique>                                <point_montage>  <type>  <options>       <dump>  <pass>
UUID=89a7f342-30e4-4d8b-90f7-111111111111        /boot            ext4    defaults          0       2
UUID=df5a0256-42bc-442a-9cb6-222222222222        /                ext4    defaults,noatime  0       1
UUID=B14E-0A33                                  /boot/efi        vfat    umask=0077        0       1
UUID=97cf2984-7e9b-4395-8859-444444444444        /home            ext4    defaults,nosuid   0       2
/dev/vg_data/lv_web                             /var/www         ext4    defaults,noexec   0       2
UUID=59e850b5-e427-4a0b-8524-333333333333        none             swap    sw                0       0

    35.4.1 V.6.4.1 Analyse détaillée des 6 champs

    35.4.1.1 V.6.4.1.1 Colonne 1 : Périphérique de stockage

    Désigne la source : un identifiant UUID=..., un nom LABEL=..., un fichier sous /dev (/dev/sda2, /dev/vg/lv), ou un partage réseau NFS (serveur:/partage).

    35.4.1.2 V.6.4.1.2 Colonne 2 : Point de montage

    Chemin absolu du répertoire où le contenu sera greffé (/, /home, /var). Pour la mémoire d'échange Swap, on indique conventionnellement none ou swap.

    35.4.1.3 V.6.4.1.3 Colonne 3 : Type de système de fichiers

    Format utilisé : ext4, xfs, vfat, swap, iso9660, nfs, etc.

    35.4.1.4 V.6.4.1.4 Colonne 4 : Options de montage

    Mots-clés séparés par des virgules (sans aucun espace !) :

    • defaults : Groupe d'options par défaut standard équivalent à rw, suid, dev, exec, auto, nouser, async.
    • ro / rw : Montage en lecture seule (Read-Only) ou lecture-écriture (Read-Write).
    • noexec : Interdit l'exécution de tout binaire sur la partition (sécurité pour /tmp et /var/tmp).
    • nosuid : Neutralise les bits SUID et SGID pour empêcher les escalades de privilèges.
    • nodev : Interdit l'interprétation des fichiers spéciaux de périphériques.
    • noatime : Désactive la mise à jour de la date de dernier accès à chaque lecture de fichier (gain substantiel de performances sur SSD).
    • auto / noauto : Autorise (ou empêche) le montage automatique lors de l'exécution de mount -a ou au démarrage.
    • user / nouser : Permet (ou interdit) à un utilisateur ordinaire sans privilège sudo de monter le périphérique (fréquent pour les lecteurs CD/DVD ou clés amovibles).
    • nofail : Permet au système de poursuivre son démarrage même si le périphérique est absent ou débranché.

    35.4.1.5 V.6.4.1.5 Colonne 5 : Fréquence de sauvegarde dump

    Indique si le système de fichiers doit être sauvegardé par l'ancien utilitaire Unix dump.

    • 0 : Ignorer (valeur universelle aujourd'hui).
    • 1 : Sauvegarde quotidienne.

    35.4.1.6 V.6.4.1.6 Colonne 6 : Ordre de vérification fsck (pass number)

    Définit l'ordre dans lequel l'utilitaire fsck vérifie la cohérence du système de fichiers au démarrage :

    • 1 : Priorité absolue, réservé exclusivement au système de fichiers racine /.
    • 2 : Autres systèmes de fichiers locaux à vérifier après la racine (ex. /boot, /home, /var).
    • 0 : Aucune vérification au démarrage. Obligatoire pour la mémoire swap, les partages réseau NFS, les systèmes de fichiers Windows (vfat, ntfs) et les partitions XFS (qui gèrent leur propre journalisation interne).

    35.5 V.6.5 Règle de sécurité absolue : Le test avec mount -a

    Une seule erreur de syntaxe dans /etc/fstab (faute de frappe sur un UUID, option inexistante) peut bloquer le démarrage de Linux et basculer la machine en mode d'urgence (emergency mode).

    Pour valider vos modifications sans risquer de corrompre le prochain démarrage, exécutez toujours :

    $ sudo mount -a

    Si cette commande ne renvoie aucun message d'erreur, votre configuration /etc/fstab est saine et fonctionnelle.

    35.6 V.6.6 Consultation de l'état des montages

    35.6.1 V.6.6.1 Arborescence interactive avec findmnt

    La commande findmnt produit une visualisation hiérarchique claire et structurée de tous les systèmes de fichiers actifs :

    $ findmnt
TARGET                                SOURCE                  FSTYPE     OPTIONS
/                                     /dev/mapper/vg-root     ext4       rw,relatime,errors=remount-ro
├─/boot                               /dev/sda2               ext4       rw,relatime
│ └─/boot/efi                         /dev/sda1               vfat       rw,relatime,fmask=0077,dmask=0077
├─/home                               /dev/mapper/vg-home     ext4       rw,nosuid,relatime
└─/var/www                            /dev/mapper/vg_data-lv_web ext4    rw,noexec,relatime

    35.6.2 V.6.6.2 Vue du noyau : /proc/mounts et /etc/mtab

    • /proc/mounts est un pseudo-fichier du noyau reflétant instantanément et fidèlement l'état réel de tous les points de montage et des options actives.
    • /etc/mtab est historiquement le fichier répertoriant les systèmes de fichiers montés. Sur les distributions modernes, /etc/mtab est simplement un lien symbolique pointant vers /proc/mounts.
