    32. V.3 Systèmes de fichiers et création

    Une fois un disque partitionné, les partitions brutes ne peuvent pas stocker de données telles quelles. Il est indispensable de les formater en y créant une structure logique appelée système de fichiers (filesystem).

    Cette section aborde les mécanismes internes d'un système de fichiers (inodes, superbloc, journalisation), présente les formats majeurs sous Linux et détaille les commandes de création avec la famille d'utilitaires mkfs, en conformité avec l'objectif LPIC-1 104.1.

    32.1 V.3.1 Principes fondamentaux d'un système de fichiers

    Un système de fichiers régit la façon dont les fichiers sont nommés, stockés, hiérarchisés et extraits sur un support de stockage physique ou virtuel. Les concepts ci dessous sont détaillés dans la suite :

    • Les blocs de données : C'est la partie où est stocké le contenu brut des fichiers.
    • Les inodes : C'est la partie où sont stockées les métadonnées des fichiers (droits, taille, UID, pointeurs vers les blocs de données).
    • Le superbloc : C'est la partie où sont stockées les métadonnées du système de fichiers (taille, état, nombre de blocs libres, etc.).
    • La journalisation : C'est une structure de données qui enregistre les modifications apportées au système de fichiers avant qu'elles ne soient écrites sur le disque.

    32.1.1 V.3.1.1 Les blocs de données (Data Blocks)

    L'espace d'une partition est subdivisé en blocs contigus d'une taille fixe (généralement 4096 octets / 4 Kio par défaut). Lorsqu'un fichier est écrit, le système lui alloue un nombre entier de blocs. Même un fichier d'un seul octet consommera au minimum un bloc complet de 4 Kio sur le disque.

    32.1.2 V.3.1.2 Les inodes (Index Nodes)

    Un inode est une structure de données interne enregistrant toutes les caractéristiques d'un fichier, à l'exception notable de son nom :

    • Le type de fichier (ordinaire, répertoire, lien, socket, tube, périphérique).
    • Les permissions d'accès Unix (rwxr-xr-x).
    • L'identifiant du propriétaire (UID) et du groupe (GID).
    • La taille en octets.
    • Les horodatages (timestamps) : date de dernier accès (atime), de modification du contenu (mtime), de changement de métadonnées (ctime).
    • Les pointeurs vers les blocs de données contenant le contenu effectif du fichier.

    Le nom du fichier n'est pas dans son inode

    Pour le noyau Linux, un fichier n'est désigné que par son numéro d'inode (visible avec ls -i). Le nom textuel du fichier est conservé uniquement dans le répertoire parent, qui sert de simple table d'association reliant une chaîne de caractères à un numéro d'inode.

    32.1.3 V.3.1.3 Le superbloc (Superblock)

    Le superbloc est l'en-tête vital du système de fichiers. Il conserve ses paramètres globaux :

    • Le type de système de fichiers.
    • Le nombre total de blocs et le nombre de blocs libres.
    • Le nombre total d'inodes et le nombre d'inodes libres.
    • L'état du système de fichiers (clean ou dirty après un arrêt inopiné).
    • Des copies redondantes de sauvegarde (backup superblocks) sont disséminées sur la partition pour permettre la restauration en cas de corruption.

    32.1.4 V.3.1.4 La journalisation (Journaling)

    Sur les systèmes de fichiers non journalisés (comme ext2), une coupure de courant pendant une écriture laisse la partition dans un état incohérent, obligeant le système à scanner l'intégralité du disque bloc par bloc au démarrage suivant (fsck), ce qui peut prendre plusieurs heures.

    Les systèmes modernes (ext4, XFS) intègrent un journal circulaire :

    1. Avant d'écrire sur le disque, l'intention de modification des métadonnées est d'abord consignée dans le journal.
    2. L'écriture est ensuite effectuée dans la table d'inodes et les blocs de données.
    3. L'opération est validée (committed) dans le journal.

    En cas de crash système, le noyau se contente de relire le journal en quelques secondes pour terminer les opérations en cours ou annuler les opérations incomplètes.

    32.2 V.3.2 Panorama des systèmes de fichiers sous Linux

    32.2.1 V.3.2.1 Famille ext (Extended Filesystem)

    Format Caractéristiques principales Usage
    ext2 Format historique sans journalisation. Très simple, n'use pas les cycles d'écriture. Clés USB anciennes, mémoires flash embarquées.
    ext3 Ajout de la journalisation à ext2 avec rétrocompatibilité totale. Anciennes installations Linux.
    ext4 Standard incontournable. Utilise des extents (allocation de blocs contigus réduisant la fragmentation), supporte des volumes jusqu'à 1 Eio (Exbioctet = 1 048 576 To = 1024^2 Gio) et des fichiers jusqu'à 16 Tio. Horodatage à la nanoseconde. Système de fichiers par défaut sur Debian, Ubuntu, Linux Mint.

    32.2.2 V.3.2.2 Système de fichiers XFS

    Développé initialement par Silicon Graphics (SGI) pour les supercalculateurs IRIX, XFS est un système 64 bits taillé pour la haute performance et les très grands volumes de données :

    • Allocation dynamique des inodes (impossible d'épuiser prématurément la table des inodes).
    • Performances exceptionnelles en entrées/sorties parallèles.
    • Système de fichiers par défaut sur les distributions de la famille Red Hat Enterprise Linux (RHEL, CentOS, Rocky Linux, Fedora Server).
    • Règle capitale LPIC-1 : Un système XFS peut être agrandi à chaud (xfs_growfs), mais il ne peut JAMAIS être réduit !

    32.2.3 V.3.2.3 Format VFAT / FAT32

    Système de fichiers universel issu de l'univers Windows :

    • Ne gère pas les permissions Unix (propriétaires, droits rwx, liens symboliques).
    • Limite structurelle : la taille d'un fichier individuel ne peut excéder 4 Gio.
    • Usage incontournable sous Linux : C'est le format obligatoire pour la partition système EFI (/boot/efi) sur les systèmes UEFI.

    32.2.4 V.3.2.4 Autres systèmes notables

    • Btrfs : Système moderne fondé sur le principe du Copy-on-Write (CoW), offrant instantanés (snapshots), sous-volumes et gestion RAID logicielle intégrée (défaut sur openSUSE et Fedora Workstation).
    • exFAT : Évolution de FAT32 permettant de lever la limite de 4 Gio, standard sur les cartes mémoire SDXC modernes.

    32.3 V.3.3 Création et formatage avec la famille mkfs

    La commande standard pour formater une partition est mkfs (make filesystem). Elle agit comme un sélecteur appelant les binaires dédiés selon le type demandé : mkfs.<type>.

    Les deux syntaxes suivantes sont strictement équivalentes :

    • Syntaxe générique avec l'option -t

      $ sudo mkfs -t ext4 /dev/sdb1

    • Syntaxe directe par binaire dédié (recommandée)

      $ sudo mkfs.ext4 /dev/sdb1

    32.3.1 V.3.3.1 Formatage en ext4 avec mkfs.ext4

    $ sudo mkfs.ext4 /dev/sdb1
mke2fs 1.46.5 (30-Dec-2021)
Creating filesystem with 2621440 4k blocks and 655360 inodes
Filesystem UUID: 98a3b547-7592-4fcf-bc08-41584cb02ff0
Superblock backups stored on blocks: 
    32768, 98304, 163840, 229376, 294912, 819200, 884736, 1605632

Allocating group tables: done                            
Writing inode tables: done                            
Creating journal (16384 blocks): done
Writing superblocks and filesystem accounting information: done

    Options fréquentes de mkfs.ext4 :

    • -L <LABEL> : Assigne une étiquette textuelle (nom lisible) à la partition.
    • -b <taille> : Spécifie la taille des blocs en octets (1024, 2048 ou 4096).
    • -m <pourcentage> : Définit le pourcentage d'espace réservé au superutilisateur root (5 % par défaut). Cela évite qu'un utilisateur ordinaire ne bloque les services système vitaux en saturant le disque.
    • -N <nombre> : Impose manuellement le nombre d'inodes à créer.

    • Exemple : formate avec le label "DONNEES" et 1% d'espace réservé au root

      $ sudo mkfs.ext4 -L DONNEES -m 1 /dev/sdb1

    32.3.2 V.3.3.2 Formatage en XFS avec mkfs.xfs

    Le binaire dédié est mkfs.xfs :

    $ sudo mkfs.xfs -L DATA_VOL /dev/sdb2
meta-data=/dev/sdb2              isize=512    agcount=4, agsize=655360 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=1        finobt=1, sparse=1, rmapbt=0
data     =                       bsize=4096   blocks=2621440, imaxpct=25
         =                       sunit=0      swidth=0 blks
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=2560, version=2
         =                       sectsz=512   sunit=0 blks, lazy-count=1
realtime =none                   extsz=4096   blocks=0, rtextents=0

    Option courante :

    • -f : Force l'écrasement si un système de fichiers existant est déjà détecté.

    32.3.3 V.3.3.3 Formatage en vfat (Partition EFI ou clé USB) avec mkfs.vfat

    Pour formater la partition EFI en FAT32 :

    $ sudo mkfs.vfat -F 32 -n EFI_SYSTEM /dev/sda1
mkfs.fat 4.2 (2021-01-31)

    Options :

    • -F 32 : Impose le standard FAT32 (12, 16 ou 32).
    • -n <NOM> : Attribue un nom de volume (limité à 11 caractères).

    32.4 V.3.4 Vérification après formatage : blkid et lsblk -f

    Après avoir créé un système de fichiers, l'administrateur doit vérifier la génération de l'UUID (Universally Unique Identifier) :

    $ sudo blkid /dev/sdb1
/dev/sdb1: LABEL="DONNEES" UUID="98a3b547-7592-4fcf-bc08-41584cb02ff0" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="b5092a72-01"

    L'UUID est un identifiant de 128 bits garanti unique au monde, généré au moment du formatage. Il est universellement utilisé pour monter les volumes de façon permanente dans /etc/fstab.

    $ lsblk -f 
NAME        FSTYPE LABEL           UUID                                 MOUNTPOINTS
sda                                                                       
├─sda1      vfat   EFI_SYSTEM    5F27-94F4                            /boot/efi
├─sda2      ext4   Boot_Linux    b894c5e3-2071-4860-88f6-083256b4890f /boot
└─sda3      swap                 8de6f1f9-07f3-474c-8750-9bb9b9df1640 [SWAP]
sdb                                                                       
└─sdb1      ext4   DONNEES       98a3b547-7592-4fcf-bc08-41584cb02ff0 /mnt/data
sdc                                                                       
└─sdc1      vfat   SDCard        6E46-95D6                            /mnt/sdcard
