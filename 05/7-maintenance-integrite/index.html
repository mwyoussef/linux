    36. V.7 Maintenance et intégrité des systèmes de fichiers

    Même sur un système d'exploitation stable, les systèmes de fichiers sont soumis aux contraintes de coupures de courant brutales, de pannes matérielles de contrôleurs ou de saturation progressive de l'espace.

    L'administrateur Linux doit être capable d'auditer en continu l'espace disque et les tables d'inodes, de vérifier et réparer les anomalies structurelles, et d'ajuster finement les paramètres des superblocs.

    Cette section couvre l'ensemble des compétences requises par l'objectif LPIC-1 104.2 (Maintain the integrity of filesystems).

    36.1 V.7.1 Surveillance de la capacité : Espace disque et Inodes

    36.1.1 V.7.1.1 Surveillance de l'espace avec df

    La commande df rapporte l'espace disponible sur l'ensemble des systèmes de fichiers actuellement montés.

    $ df -h
Sys. de fichiers        Taille Utilisé Dispo Uti% Monté sur
udev                      7,8G       0  7,8G   0% /dev
tmpfs                     1,6G    1,8M  1,6G   1% /run
/dev/mapper/vg-root        49G     14G   33G  30% /
/dev/sda2                 974M    210M  697M  24% /boot
/dev/sda1                 511M    5,3M  506M   2% /boot/efi
/dev/mapper/vg-home       165G     28G  129G  18% /home
    • L'option -h (human-readable) convertit les tailles en puissances de 1024 (Kio, Mio, Gio) pour une lecture immédiate.
    • L'option -T ajoute une colonne indiquant le type de système de fichiers (ext4, xfs, vfat).

    36.1.2 V.7.1.2 Piège classique : L'épuisement des Inodes (df -i)

    Un disque peut être totalement bloqué pour cause de saturation, alors même que df -h indique qu'il reste plusieurs dizaines de gigaoctets libres !

    Ce problème survient lorsque la table des inodes est épuisée. Si des applications génèrent des millions de fichiers minuscules (comme des sessions PHP orphelines, des spools d'emails ou des fichiers de micro-logs), chaque fichier consomme un inode. Dès que tous les inodes alloués lors du formatage sont pris, le système renvoie l'erreur fatale :
    No space left on device.

    L'option -i permet de surveiller la saturation des inodes :

    $ df -i
Sys. de fichiers          Inodes IUtil.  ILibre IUti% Monté sur
/dev/mapper/vg-root      3276800 245120 3031680    8% /
/dev/mapper/vg-home     11010048 812400 10197648   8% /home
/dev/sdb1                 655360 655360       0  100% /var/spool/mail
    (Dans cet exemple, /dev/sdb1 est complètement saturé à 100 % d'inodes : il est impossible d'y créer le moindre fichier).

    36.2 V.7.2 Mesure de l'occupation par dossier : du (Disk Usage)

    Tandis que df interroge le superbloc des partitions montées, la commande du parcourt l'arborescence des répertoires pour calculer la taille cumulée des fichiers.

    // Mesurer la taille totale d'un répertoire spécifique
$ sudo du -sh /var/log
2,4G    /var/log

// Analyser les sous-dossiers immédiats les plus volumineux (classés par taille décroissante)
$ sudo du -h --max-depth=1 /var | sort -hr | head -n 5
18G     /var
12G     /var/lib
3,2G    /var/log
1,8G    /var/cache
520M    /var/tmp

    Options essentielles de du :

    • -s (summary) : Affiche uniquement le total général du dossier cible, sans lister chaque fichier un par un.
    • -h (human-readable) : Formate les tailles en Ko, Mo, Go.
    • -c (grand total) : Ajoute une ligne de somme globale à la fin du rapport.
    • --max-depth=N (ou -d N) : Limite la descente récursive aux sous-répertoires de niveau N.

    36.3 V.7.3 Vérification et réparation avec fsck (File System Consistency Check)

    L'utilitaire fsck recherche et répare les incohérences internes d'un système de fichiers (blocs orphelins, décalages de compteurs de références, blocs marqués libres mais utilisés).

    À l'instar de mkfs, fsck est un frontal (wrapper) qui invoque en réalité le réparateur spécifique du format détecté : fsck.ext4, e2fsck, fsck.vfat.

    RÈGLE ABSOLUE DE SÉCURITÉ : Ne JAMAIS réparer un système monté en RW

    Il ne faut JAMAIS exécuter fsck sur un système de fichiers monté en lecture-écriture (Read-Write).
    Pendant que fsck tente de réorganiser les tables d'inodes, le noyau Linux continue d'écrire en mémoire tampon. Cette confrontation détruit irrémédiablement la structure des données !

    Pour réparer un système de fichiers en toute sécurité, trois approches sont possibles :

    1. Démonter préalablement la partition : 

      $ sudo umount /dev/sdb1
$ sudo fsck -f -y /dev/sdb1

    2. Remonter la partition en lecture seule (si démontage impossible) : 

      $ sudo mount -o remount,ro /home
$ sudo fsck -f -y /home
$ sudo mount -o remount,rw /home

    3. Démarrer sur un support externe (Live USB ou mode de secours rescue) pour réparer la partition racine /.

    36.3.1 V.7.3.1 Options indispensables de fsck / e2fsck

    Option Rôle
    -f Force. Force la vérification même si le système de fichiers est étiqueté comme propre (clean).
    -y Yes. Répond automatiquement par l'affirmative à toutes les propositions de correction de blocs ou d'inodes (évite d'appuyer des centaines de fois sur Entrée).
    -n No. Effectue une simple vérification en lecture seule sans modifier ni réparer aucun bloc.
    -c Recherche les blocs défectueux physiques (bad blocks) et les ajoute à la liste noire pour qu'ils ne soient plus jamais alloués.

    36.3.2 V.7.3.2 Le répertoire lost+found

    À la racine de chaque partition formatée en ext2/ext3/ext4, vous trouverez un dossier réservé nommé lost+found.
    Lors d'une réparation, lorsque fsck récupère des fragments de fichiers intacts mais dont le nom textuel ou le chemin du répertoire parent a disparu de l'arborescence, il les stocke sous forme d'inodess orphelins dans /lost+found (ex. /lost+found/#24891). L'administrateur peut ensuite inspecter leur contenu pour tenter de les identifier.

    36.4 V.7.4 Administration des métadonnées ext2/ext3/ext4 : tune2fs et dumpe2fs

    Pour les systèmes de la famille ext, Linux propose deux utilitaires de bas niveau très puissants.

    36.4.1 V.7.4.1 Paramétrage avancé avec tune2fs

    tune2fs permet d'ajuster les métadonnées et le comportement du système de fichiers sur une partition existante :

    // 1. Attribuer ou modifier le label d'une partition
$ sudo tune2fs -L "DATA_BACKUP" /dev/sdb1

// 2. Réduire l'espace réservé au root de 5% à 1% (libère de l'espace pour les utilisateurs)
$ sudo tune2fs -m 1 /dev/sdb1

// 3. Forcer un contrôle fsck tous les 30 montages
$ sudo tune2fs -c 30 /dev/sdb1

// 4. Désactiver la vérification basée sur le nombre de montages (valeur 0 ou -1)
$ sudo tune2fs -c 0 /dev/sdb1

// 5. Définir un intervalle temporel de vérification obligatoire (ex. 6 mois)
$ sudo tune2fs -i 6m /dev/sdb1

    36.4.2 V.7.4.2 Exploration du superbloc avec dumpe2fs

    La commande dumpe2fs extrait l'intégralité des informations techniques conservées dans le superbloc et les groupes de blocs d'une partition ext :

    36.5 V.7.5 Maintenance et outils spécifiques pour XFS

    Les systèmes de fichiers XFS ne peuvent pas être vérifiés avec fsck ni administrés avec tune2fs. Ils possèdent leur propre suite d'outils dédiés :

    36.5.1 V.7.5.1 Réparation XFS avec xfs_repair

    Comme pour fsck, le système de fichiers doit obligatoirement être démonté :

    $ sudo umount /mnt/data_xfs
$ sudo xfs_repair /dev/sdb2
    L'option -n permet d'exécuter un diagnostic en lecture seule sans appliquer de modification.

    36.5.2 V.7.5.2 Gestion des métadonnées avec xfs_admin

    Permet de modifier les étiquettes et UUID d'une partition XFS démontée :

    // Modifier le LABEL
$ sudo xfs_admin -L "ARCHIVES" /dev/sdb2

// Régénérer un nouvel UUID
$ sudo xfs_admin -U generate /dev/sdb2

    36.5.3 V.7.5.3 Défragmentation avec xfs_fsr (Filesystem Reorganizer)

    Contrairement à la plupart des systèmes Linux qui gèrent très bien la fragmentation, XFS propose un utilitaire dédié pour défragmenter et réorganiser les extents à chaud :

    $ sudo xfs_fsr /dev/sdb2
