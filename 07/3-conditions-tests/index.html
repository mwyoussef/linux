    49. VII.3 Structures conditionnelles et tests

    Pour qu'un script prenne des décisions en fonction d'un fichier, d'une valeur numérique, d'une chaîne de caractères ou du résultat d'une commande, Bash propose les structures if / then / elif / else / fi et case / esac.

    49.1 VII.3.1 Syntaxe if / then / else et commande test

    if condition; then
  commande1
elif autre_condition; then
  commande2
else
  commande3
fi

    Pour évaluer une expression, deux écritures strictement équivalentes existent :

    • Écriture préférée : [ expression ] (attention : les espaces après [ et avant ] sont obligatoires !)
    • Écriture équivalente : test expression

    49.2 VII.3.2 Opérateurs de test

    49.2.1 VII.3.2.1 Comparaisons numériques

    Opérateur Signification Anglais
    -eq égal à equal to
    -ne différent de not equal to
    -lt inférieur à less than
    -le inférieur ou égal à less than or equal to
    -gt supérieur à greater than
    -ge supérieur ou égal à greater than or equal to

    Exemple : if [ "$#" -lt 1 ]; then ...

    49.2.2 VII.3.2.2 Comparaisons de chaînes de caractères

    Opérateur Signification
    = (ou == en Bash) Les deux chaînes sont identiques ([ "$a" = "oui" ]).
    != Les deux chaînes sont différentes.
    -z "$str" La chaîne est vide (zero length).
    -n "$str" La chaîne est non vide.

    Toujours entourer les variables de guillemets dans [ ... ]

    Écrivez [ "$var" = "oui" ] et non [ $var = "oui" ]. Si $var est vide, la commande devient [ = "oui" ] et provoque une erreur de syntaxe.

    49.2.3 VII.3.2.3 Tests sur les fichiers et répertoires

    Test Vérifie que…
    -e $fichier Le fichier ou dossier existe.
    -d $fichier C'est un répertoire (rappel : sous Linux, tout est fichier).
    -f $fichier C'est un fichier ordinaire, pas un dossier.
    -L $fichier C'est un lien symbolique.
    -r $fichier Le fichier est lisible (r).
    -w $fichier Le fichier est modifiable (w).
    -x $fichier Le fichier est exécutable (x).
    $f1 -nt $f2 f1 est plus récent que f2 (newer than).
    $f1 -ot $f2 f1 est plus ancien que f2 (older than).

    49.3 VII.3.3 Exemples pratiques de tests

    49.3.1 VII.3.3.1 Vérifier l'existence d'un chemin dans une fonction (script4a.sh)

    #!/bin/bash
# script4a.sh
read -p "Dossier ou fichier à vérifier ? " passwdir

checkdir() {
  if [ -e "$passwdir" ]; then
    echo "$passwdir existe"
  else
    echo "$passwdir n'existe pas"
  fi
}

checkdir
exit 0

    49.3.2 VII.3.3.2 Recréer un répertoire temporaire à neuf (01_tmp.sh)

    #!/bin/sh
# 01_tmp.sh
dir="${HOME}/tmp/"

if [ -d "${dir}" ]; then
  rm -rf "${dir}"
  echo "Dossier ${dir} effacé"
fi

mkdir -p "${dir}"
echo "Dossier ${dir} créé"

    49.4 VII.3.4 Structure professionnelle d'un script : usage() et main()

    Un bon script d'administration valide d'abord ses arguments avec $# avant d'exécuter sa logique métier :

    #!/bin/bash
target="$1"

usage() {
  echo "Usage: $0 <fichier/dossier>"
  exit 1
}

main() {
  ls -l "$target"
  echo "Lignes : $(wc -l < "$target")"
  stat "$target"
}

# Aiguillage sur le nombre de paramètres ($#)
if [ $# -lt 1 ]; then
  usage
elif [ $# -eq 1 ]; then
  main
else
  usage
fi

exit 0
    • Aucun paramètre (-lt 1) ou trop de paramètres → appel de usage() qui affiche l'aide et quitte avec le code d'erreur 1.
    • Exactement un paramètre (-eq 1) → exécution de main().

    49.5 VII.3.5 Choix multiple : case ... esac

    Lorsque plusieurs valeurs doivent être testées sur une même variable (menus interactifs, analyse d'options), la structure case est plus claire qu'une longue suite de if / elif :

    #!/bin/sh
# script8.sh
read -p "Afficher les fichiers cachés (oui/non) : " reponse

case "$reponse" in
  oui|OUI|o)
    clear
    ls -a
    ;;
  non|NON|n)
    ls
    ;;
  *)
    echo "Répondez par oui ou non."
    ;;
esac

exit 0
    • case "$var" in : compare la valeur de la variable à chaque motif.
    • ) : introduit les instructions de la branche (possibilité de grouper plusieurs motifs avec |).
    • ;; : termine obligatoirement chaque branche.
    • *) : branche par défaut traitant tous les cas imprévus.
    • esac : ferme le bloc (case écrit à l'envers, comme fi pour if).
