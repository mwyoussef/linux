    18. III.2 Gestion des permissions

    18.1 III.2.1 Modèle de permissions Unix

    18.1.1 III.2.1.1 Propriétaire, groupe et autres

    Chaque fichier et répertoire sous Linux est rattaché à trois entités distinctes : - Le propriétaire (user ou u) : l'utilisateur qui possède le fichier. - Le groupe propriétaire (group ou g) : le groupe d'utilisateurs partageant des accès communs. - Les autres (others ou o) : tous les autres utilisateurs du système qui ne sont ni propriétaires ni membres du groupe.

    Les permissions sont affichées via la commande ls -l :

    $ ls -l fichier.txt
-rw-r----- 1 alice dev 1024 Feb 10 12:00 fichier.txt

    Décomposition des champs :

    Composante Exemple Signification
    Type de fichier - Premier caractère : - pour un fichier ordinaire, d pour un répertoire (directory), l pour un lien symbolique.
    Permissions rw-r----- 9 caractères représentant les droits du Propriétaire (rw-), du Groupe (r--) et des Autres (---).
    Nombre de liens 1 Nombre de liens physiques (hard links) pointant vers cet inode.
    Propriétaire alice Compte utilisateur propriétaire du fichier.
    Groupe dev Groupe propriétaire associé au fichier.
    Taille 1024 Taille en octets (utilisez ls -lh pour afficher en Kio, Mio).
    Horodatage Feb 10 12:00 Date et heure de dernière modification du contenu.
    Nom fichier.txt Nom du fichier ou répertoire.

    18.1.2 III.2.1.2 Types de droits

    Linux attribue trois droits élémentaires combinables :

    • r (read) : droit de lecture.
    • w (write) : droit d'écriture et de modification.
    • x (execute) : droit d'exécution ou de traversée.

    18.1.3 III.2.1.3 Impact des droits sur les fichiers et les dossiers

    La signification d'une permission diffère profondément selon qu'elle s'applique à un fichier ordinaire ou à un répertoire :

    Permission Sur un Fichier Sur un Répertoire
    r (read) Lire le contenu du fichier (ex. cat, less, cp). Lister les noms des fichiers contenus à l'intérieur (ex. ls).
    w (write) Modifier le contenu du fichier (ex. nano, echo >>). Créer, supprimer ou renommer des fichiers dans ce dossier.
    x (execute) Exécuter le fichier en tant que programme ou script. Traverser le répertoire pour accéder à ses métadonnées, sous-dossiers ou ouvrir un fichier connu (cd, accès direct).

    Pièges classiques sur les permissions de répertoires

    • Le piège du droit w sur répertoire : Si un utilisateur possède le droit d'écriture w sur un répertoire, il peut supprimer ou renommer n'importe quel fichier à l'intérieur, même si ce fichier appartient à quelqu'un d'autre et possède des droits en lecture seule (-r--r--r--) !
    • Le rôle indispensable du droit x : Sans le droit x sur un répertoire, il est impossible de faire un cd dedans, ni d'accéder au contenu d'un fichier qu'il abrite, même si vous en possédez les droits complets rwx.

    Règle de la première correspondance (First Match Wins)

    Lorsqu'un processus tente d'accéder à un fichier : 1. Si l'utilisateur est le propriétaire, seuls les droits u s'appliquent. 2. Sinon, si l'utilisateur appartient au groupe propriétaire, seuls les droits g s'appliquent. 3. Sinon, seuls les droits o s'appliquent.

    Conséquence : Si le propriétaire a les droits --- et que les autres ont rwx, le propriétaire se verra refuser l'accès ! Le système ne cumule pas les permissions et s'arrête à la première catégorie correspondante.

    18.2 III.2.2 Changement de propriétaire et de groupe

    La modification des propriétaires requiert les privilèges root (via sudo).

    18.2.1 III.2.2.1 Commande chown

    chown (change owner) modifie le propriétaire et, optionnellement, le groupe d'un fichier ou répertoire.

    Situation initiale :

    $ ls -l fichier.txt
-rw-r----- 1 alice dev 1024 Feb 10 12:00 fichier.txt

    • Changer uniquement le propriétaire : 

      $ sudo chown bob fichier.txt
$ ls -l fichier.txt 
-rw-r----- 1 bob dev 1024 Feb 10 12:00 fichier.txt

    • Changer simultanément le propriétaire et le groupe (syntaxe utilisateur:groupe) : 

      $ sudo chown bob:www-data fichier.txt 
$ ls -l fichier.txt
-rw-r----- 1 bob www-data 1024 Feb 10 12:00 fichier.txt

    • Appliquer récursivement à tout un dossier avec l’option -R : 

      $ sudo chown -R bob:www-data /projet

    18.2.2 III.2.2.2 Commande chgrp

    chgrp (change group) modifie exclusivement le groupe d'un fichier. Contrairement à chown, un utilisateur ordinaire peut utiliser chgrp s'il est propriétaire du fichier et déjà membre du nouveau groupe visé :

    $ chgrp www-data fichier.txt

    Avec récursion sur un dossier :

    $ chgrp -R www-data /projet

    18.3 III.2.3 Modification des permissions

    La commande chmod (change mode) permet de modifier les permissions d’accès. Seuls le propriétaire du fichier et le superutilisateur root peuvent changer les droits d'un fichier.

    chmod accepte deux notations : symbolique (relative) et octale (absolue).

    18.3.1 III.2.3.1 Notation symbolique

    La notation symbolique combine : - La cible : u (user/owner), g (group), o (others), ou a (all, équivalent à ugo). - L'opérateur : + (ajouter), - (retirer), = (définir exactement). - Le droit : r, w, x.

    Exemples :

    • Ajouter l’exécution pour le propriétaire : 

      $ chmod u+x script.sh

    • Retirer les droits d’écriture pour les autres : 

      $ chmod o-w fichier.txt

    • Ajouter les droits de lecture et écriture pour le groupe : 

      $ chmod g+rw fichier.txt

    • Définir strictement rwxr-x--- (tous les droits pour u, lecture/exécution pour g, aucun droit pour o) : 

      $ chmod u=rwx,g=rx,o= fichier.txt

    18.3.2 III.2.3.2 Notation numérique (octale)

    En notation octale, chaque catégorie d'utilisateurs (u, g, o) est représentée par un chiffre compris entre 0 et 7, obtenu par la somme pondérée des droits actifs :

    • r (lecture) = 4 ($2^2$, soit 100 en binaire)
    • w (écriture) = 2 ($2^1$, soit 010 en binaire)
    • x (exécution) = 1 ($2^0$, soit 001 en binaire)
    • - (aucun droit) = 0

    Table des combinaisons fréquentes :

    Valeur octale Binaire Symbolique Description
    7 111 rwx Lecture, écriture et exécution
    6 110 rw- Lecture et écriture
    5 101 r-x Lecture et exécution
    4 100 r-- Lecture seule
    0 000 --- Aucun droit

    Exemples usuels :

    • 644 (rw-r--r--) : droit classique pour un fichier texte (lecture/écriture pour le propriétaire, lecture seule pour tous les autres) : 

      $ chmod 644 fichier.txt

    • 755 (rwxr-xr-x) : droit classique pour un script, un binaire exécutable ou un répertoire : 

      $ chmod 755 script.sh

    • 700 (rwx------) : accès exclusif au propriétaire (ex. dossier ~/.ssh/ ou scripts confidentiels) : 

      $ chmod 700 ~/.ssh

    • 600 (rw-------) : lecture/écriture exclusive au propriétaire (ex. clé privée SSH ~/.ssh/id_rsa) : 

      $ chmod 600 ~/.ssh/id_rsa

    • 770 (rwxrwx---) : espace partagé entre le propriétaire et les membres du groupe : 

      $ chmod 770 /projet

    18.3.3 III.2.3.3 Modification récursive et l'astuce du X majuscule

    Pour modifier récursivement les droits d'une arborescence entière, on utilise l'option -R :

    $ chmod -R 755 /var/www/html/

    L'option magique chmod +X (X majuscule)

    Si vous appliquez récursivement chmod -R 755, tous vos fichiers ordinaires deviendront exécutables, ce qui est une mauvaise pratique.

    Pour accorder l'exécution uniquement aux répertoires (pour permettre de les traverser) sans rendre exécutables les fichiers ordinaires :

    $ chmod -R a+rX mon_dossier/

    Le X majuscule n'applique le droit d'exécution qu'aux répertoires, ou aux fichiers qui possédaient déjà au moins un droit d'exécution.
