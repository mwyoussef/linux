    17. III.1 Gestion des utilisateurs, groupes et mots de passe

    17.1 III.1.1 Introduction

    Linux est un système d'exploitation multi-utilisateur et multitâche. À ce titre, plusieurs utilisateurs peuvent se connecter et utiliser le système simultanément, chacun disposant d'un environnement propre et de droits d'accès délimités. La gestion rigoureuse des comptes, des groupes et des politiques d'authentification constitue le premier rempart de la sécurité sous Linux.

    17.2 III.1.2 Utilisateurs et groupes sous Linux

    Un utilisateur Linux est défini par un ensemble d’attributs stockés dans le système : nom de connexion (login), identifiant numérique d'utilisateur (UID), identifiant de groupe principal (GID), commentaire descriptif (GECOS), répertoire personnel (home directory) et interpréteur de commandes par défaut (shell).

    Principe de sécurité

    L'accès aux fichiers, répertoires, périphériques et processus du système repose intégralement sur cette structure d’utilisateurs et de groupes.

    17.2.1 III.1.2.1 Utilisateur et UID

    Chaque compte est associé à un identifiant numérique unique appelé UID (User ID) :

    • UID 0 : correspond au superutilisateur root, disposant de tous les privilèges administratifs sur le système.
    • UIDs système (généralement 1 à 999) : réservés aux services d'arrière-plan et démons (daemon, syslog, www-data, systemd-resolve). Ces comptes ne possèdent généralement pas de shell interactif.
    • UIDs des utilisateurs réguliers (à partir de 1000) : attribués automatiquement lors de la création de comptes pour des utilisateurs humains (à partir de 500 sur certaines distributions plus anciennes).

    Fichiers de configuration de référence :

    • /etc/passwd : annuaire public des comptes utilisateurs.
    • /etc/shadow : mots de passe chiffrés et politiques de vieillissement (sécurisé, lisible uniquement par root).
    • /etc/login.defs : paramètres globaux par défaut pour la création des comptes (plages d'UID/GID, durée de vie des mots de passe).

    17.2.2 III.1.2.2 Groupe et GID

    Un groupe est un regroupement logique d'utilisateurs simplifiant l'attribution collective de droits et permissions :

    • Chaque groupe est identifié par un nom et un identifiant numérique GID (Group ID).
    • Groupe principal (primary group) : chaque utilisateur possède obligatoirement un groupe principal (renseigné dans son entrée /etc/passwd). Tout nouveau fichier créé appartiendra par défaut à ce groupe.
    • Groupes secondaires (supplementary groups) : un utilisateur peut être membre d'un ou plusieurs groupes secondaires pour obtenir des droits additionnels (ex. sudo, docker, adm).

    Fichiers de configuration de référence :

    • /etc/group : liste des groupes et composition des membres secondaires.
    • /etc/gshadow : mots de passe de groupe et administrateurs de groupes (rarement utilisé).

    17.3 III.1.3 Fichiers système de gestion des comptes

    17.3.1 III.1.3.1 Structure de /etc/passwd

    Le fichier /etc/passwd est accessible en lecture à tous les utilisateurs du système. Il contient une ligne par compte, composée de 7 champs délimités par des deux-points (:) :

    nom:motdepasse:UID:GID:gecos:repertoire:shell
    Champ Description Exemple
    nom Nom de connexion (login) alice
    motdepasse Historiquement le mot de passe, aujourd'hui remplacé par x (le hash réside dans /etc/shadow) x
    UID Identifiant numérique de l'utilisateur 1001
    GID Identifiant numérique du groupe principal 1001
    gecos Informations complémentaires (General Electric Comprehensive Operating System) : nom complet, numéro de bureau, téléphone Alice Dupont
    repertoire Chemin absolu vers le répertoire personnel (Home) /home/alice
    shell Interpréteur de commandes attribué lors de la session /bin/bash

    Exemple concret :

    alice:x:1001:1001:Alice Dupont:/home/alice:/bin/bash

    Comptes sans connexion interactive

    Pour les comptes de services système ou les utilisateurs dont on souhaite bloquer l'accès au terminal, le champ shell pointe vers un shell non interactif : /usr/sbin/nologin (qui affiche un message de rejet) ou /bin/false (qui quitte immédiatement avec un code d'erreur).

    17.3.2 III.1.3.2 Structure de /etc/shadow

    Le fichier /etc/shadow n'est lisible que par le compte root (droits 0640 ou 0000). Il stocke le mot de passe haché et salé (salted) ainsi que la politique de vieillissement de l'authentification :

    nom:hash:lastchg:min:max:warn:inactive:expire:reserved
    Champ Description
    nom Nom de l'utilisateur associé.
    hash Mot de passe chiffré (avec l'identifiant de l'algorithme : $6$ pour SHA-512, $y$ pour yescrypt), ou valeur spéciale (! ou * si le compte est verrouillé / n'a pas de mot de passe).
    lastchg Date du dernier changement de mot de passe (exprimée en nombre de jours écoulés depuis le 1er janvier 1970).
    min Nombre minimal de jours requis avant de pouvoir réinitialiser son mot de passe.
    max Nombre maximal de jours de validité du mot de passe (au-delà, l'utilisateur doit le changer).
    warn Nombre de jours de préavis avant expiration pendant lesquels un message d'avertissement s'affiche à la connexion.
    inactive Nombre de jours de grâce autorisés après expiration avant que le compte ne soit totalement verrouillé.
    expire Date d'expiration absolue du compte (en nombre de jours depuis le 01/01/1970).
    reserved Champ réservé pour un usage ultérieur (actuellement vide).

    Exemple :

    alice:$6$qZ7...:19714:0:90:7:14::

    17.3.3 III.1.3.3 Structure de /etc/group

    Le fichier /etc/group définit les groupes du système et répertorie leurs membres :

    nom:motdepasse:GID:liste_membres
    Champ Description
    nom Nom du groupe.
    motdepasse Remplacé par x (mots de passe de groupe gérés dans /etc/gshadow).
    GID Identifiant numérique unique du groupe.
    liste_membres Liste des comptes appartenant à ce groupe comme groupe secondaire, séparés par des virgules.

    Exemple :

    dev:x:1002:alice,bob

    Remarque : L'utilisateur dont dev est le groupe principal n'a pas besoin de figurer dans la liste_membres de cette ligne, son appartenance étant déjà actée dans /etc/passwd.

    17.4 III.1.4 Gestion des utilisateurs

    Les commandes d'administration des comptes exigent les privilèges du superutilisateur (sudo).

    17.4.1 III.1.4.1 Création d’un utilisateur (useradd)

    La commande standard sous Linux est useradd :

    $ sudo useradd -m -s /bin/bash alice

    Options usuelles :

    • -m (make home) : crée automatiquement le répertoire personnel (/home/alice) et y copie les fichiers squelettes depuis /etc/skel/.
    • -s <shell> : définit l'interpréteur de commandes (ex. /bin/bash ou /usr/sbin/nologin).
    • -g <groupe> : affecte un groupe principal personnalisé (par nom ou GID).
    • -G <groupe1,groupe2> : associe un ou plusieurs groupes secondaires dès la création.
    • -c "<texte>" : renseigne le commentaire GECOS (ex. nom complet, service).

    Après création, il est indispensable de définir un mot de passe initial pour activer le compte :

    $ sudo passwd alice

    useradd vs adduser

    • useradd est la commande native bas niveau présente sur toutes les distributions Linux.
    • adduser (notamment sous Debian et Ubuntu) est un script interactif convivial en Perl qui crée le dossier personnel, demande le mot de passe et remplit le champ GECOS pas à pas.

    17.4.2 III.1.4.2 Modification d’un compte (usermod)

    Pour ajuster les paramètres d'un utilisateur existant :

    • Modifier le nom de connexion (login) : 

      $ sudo usermod -l nouveau_nom ancien_nom

    • Déplacer le répertoire personnel : 

      $ sudo usermod -d /home/nouveau -m alice

    • Ajouter un groupe secondaire (ATTENTION AU PIÈGE) : 

      $ sudo usermod -aG dev,docker alice
      !!! danger "L'option -a est primordiale" L'option -G seule remplace l'intégralité des groupes secondaires de l'utilisateur. Pour ajouter des groupes sans écraser les appartenances existantes, vous devez impérativement combiner -a (append) et -G : -aG.

    • Changer le shell par défaut : 

      $ sudo usermod -s /bin/zsh alice

    17.4.3 III.1.4.3 Suppression d’un utilisateur (userdel)

    • Supprimer le compte tout en conservant son répertoire personnel : 

      $ sudo userdel alice

    • Supprimer le compte et détruire son répertoire personnel ainsi que sa boîte aux lettres locale : 

      $ sudo userdel -r alice

    17.4.4 III.1.4.4 Verrouillage et déverrouillage de compte

    Pour suspendre temporairement un compte sans effacer ses données :

    • Avec usermod : 

      $ sudo usermod -L alice   # Verrouille le compte (Lock)
$ sudo usermod -U alice   # Déverrouille le compte (Unlock)

    • Avec passwd : 

      $ sudo passwd -l alice   # Verrouille (ajoute '!' devant le hash dans /etc/shadow)
$ sudo passwd -u alice   # Déverrouille

    17.5 III.1.5 Gestion des groupes

    17.5.1 III.1.5.1 Création et modification des groupes (groupadd, groupmod, groupdel)

    • Créer un groupe : 

      $ sudo groupadd devops

    • Renommer un groupe : 

      $ sudo groupmod -n cloud devops

    • Changer le GID d’un groupe : 

      $ sudo groupmod -g 1500 cloud

    • Supprimer un groupe : 

      $ sudo groupdel cloud

    17.5.2 III.1.5.2 Inspection et consultation des groupes

    Plusieurs outils permettent d'analyser l'appartenance aux groupes :

    • La commande id (la plus complète) : 

      $ id alice
uid=1001(alice) gid=1001(alice) groups=1001(alice),27(sudo),1002(dev)

    • La commande groups : 

      $ groups alice
alice : alice sudo dev

    • Rechercher dans la base des groupes avec getent : 

      $ getent group dev
dev:x:1002:alice,bob

    • Lister les membres d'un groupe avec groupmems : 

      $ sudo groupmems -g dev -l
alice bob

    17.6 III.1.6 Gestion des mots de passe et vieillissement

    17.6.1 III.1.6.1 Modification du mot de passe (passwd)

    • Pour un utilisateur ordinaire (modifier son propre mot de passe) : 

      $ passwd
      Le mot de passe actuel sera requis avant de saisir le nouveau.

    • Pour l'administrateur (réinitialiser le mot de passe d’un compte) : 

      $ sudo passwd alice

    17.6.2 III.1.6.2 Politique d'expiration des mots de passe (chage)

    L’utilitaire chage (change age) ajuste la politique de sécurité des mots de passe dans /etc/shadow :

    • Afficher l’état et les dates d’expiration actuelles : 

      $ sudo chage -l alice

    • Forcer le renouvellement du mot de passe dès la prochaine connexion : 

      $ sudo chage -d 0 alice

    • Définir une durée de validité maximale de 90 jours : 

      $ sudo chage -M 90 alice

    • Définir un intervalle minimal de 7 jours entre deux modifications : 

      $ sudo chage -m 7 alice

    • Avertir l’utilisateur 7 jours avant expiration : 

      $ sudo chage -W 7 alice

    • Désactiver le compte 14 jours après expiration si non renouvelé : 

      $ sudo chage -I 14 alice
