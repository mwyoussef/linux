    20. III.4 Permissions par défaut et umask

    20.1 III.4.1 Les droits par défaut à la création

    Lorsqu'un utilisateur crée un fichier ou un répertoire, le système lui attribue automatiquement des permissions initiales. Ces permissions ne sont pas choisies au hasard : elles résultent de l'application d'un masque de création appelé umask.

    Par mesure de sécurité élémentaire sous Linux : - Un fichier ordinaire n'est jamais exécutable par défaut à sa création. Sa permission maximale théorique est 666 (rw-rw-rw-). - Un répertoire a besoin du droit d'exécution (x) pour pouvoir être traversé. Sa permission maximale théorique est 777 (rwxrwxrwx).

    Le masque umask définit les droits que le système doit retirer (masquer) à ces permissions maximales lors de chaque création :

    $$\text{Permissions effectives} = \text{Permissions maximales} \& \sim(\text{umask})$$

    (Dans la grande majorité des cas sans bits impairs sur les fichiers, cela équivaut simplement à soustraire le umask des permissions maximales).

    20.2 III.4.2 La commande umask

    La commande umask (User file-creation Mode Mask) permet d'afficher ou de modifier le masque de création de la session courante :

    $ umask
0022

    L'option -S affiche le masque sous forme symbolique compréhensible (les droits qui sont conservés) :

    $ umask -S
u=rwx,g=rx,o=rx

    20.3 III.4.3 Principe de calcul du umask

    Chaque chiffre du umask représente les permissions retirées respectivement au propriétaire (u), au groupe (g) et aux autres (o) :

    Valeur du bit umask Droits retirés Droits restants sur un Fichier (base 6) Droits restants sur un Répertoire (base 7)
    0 Aucun rw- (6) rwx (7)
    1 Exécution (x) rw- (6) rw- (6)
    2 Écriture (w) r-- (4) r-x (5)
    3 Écriture + Exécution r-- (4) r-- (4)
    7 Tous (rwx) --- (0) --- (0)

    20.4 III.4.4 Exemples pratiques de masques courants

    20.4.1 III.4.4.1 1. Masque standard serveur : 0022

    C'est la valeur par défaut sur la majorité des distributions Linux (Debian, Ubuntu, Red Hat) : - Fichiers : $666 - 022 = \mathbf{644}$ (-rw-r--r--) $\rightarrow$ lecture/écriture pour le propriétaire, lecture seule pour les autres. - Répertoires : $777 - 022 = \mathbf{755}$ (drwxr-xr-x) $\rightarrow$ accès complet pour le propriétaire, traversée et lecture pour les autres.

    $ umask 0022
$ touch rapport.txt
$ mkdir documents
$ ls -ld rapport.txt documents
-rw-r--r-- 1 alice alice 0 Feb 10 12:00 rapport.txt
drwxr-xr-x 2 alice alice 4096 Feb 10 12:00 documents

    20.4.2 III.4.4.2 2. Masque collaboratif pour groupe partagé : 0002

    Sur les distributions utilisant le schéma UPG (User Private Groups), le umask par défaut des utilisateurs réguliers est 0002 : - Fichiers : $666 - 002 = \mathbf{664}$ (-rw-rw-r--) $\rightarrow$ le groupe peut également modifier les fichiers. - Répertoires : $777 - 002 = \mathbf{775}$ (drwxrwxr-x).

    $ umask 0002
$ touch projet.txt
$ ls -l projet.txt
-rw-rw-r-- 1 alice dev 0 Feb 10 12:00 projet.txt

    20.4.3 III.4.4.3 3. Masque de sécurité confidentielle : 0027

    Recommandé en environnement professionnel pour interdire tout accès aux utilisateurs tiers : - Fichiers : $666 - 027 = \mathbf{640}$ (-rw-r-----) $\rightarrow$ le propriétaire écrit, le groupe lit, les autres n'ont aucun droit. - Répertoires : $777 - 027 = \mathbf{750}$ (drwxr-x---).

    $ umask 0027
$ touch secret.txt
$ mkdir private_dir
$ ls -ld secret.txt private_dir
-rw-r----- 1 alice dev 0 Feb 10 12:00 secret.txt
drwxr-x--- 2 alice dev 4096 Feb 10 12:00 private_dir

    20.4.4 III.4.4.4 4. Masque d'isolation stricte : 0077

    Réservé aux données hautement confidentielles : - Fichiers : $666 - 077 = \mathbf{600}$ (-rw-------) $\rightarrow$ seul le propriétaire y a accès. - Répertoires : $777 - 077 = \mathbf{700}$ (drwx------).

    $ umask 0077
$ touch cle_privee.key
$ ls -l cle_privee.key
-rw------- 1 alice alice 0 Feb 10 12:00 cle_privee.key

    20.5 III.4.5 Persistance de la configuration umask

    Toute commande umask saisie dans le terminal ne vaut que pour la session en cours. Pour rendre le réglage permanent :

    • Pour un utilisateur spécifique : ajoutez la ligne umask 0027 à la fin de son fichier ~/.bashrc ou ~/.profile.
    • Pour l'ensemble des utilisateurs du système : configurez la directive UMASK dans le fichier /etc/login.defs, ou ajoutez la commande dans /etc/profile ou un fichier /etc/profile.d/umask.sh.

    20.6 III.4.6 Bonnes pratiques de sécurité

    1. Appliquer le principe du moindre privilège : privilégiez un umask 0027 sur les serveurs de production afin de restreindre par défaut l'exposition des fichiers sensibles.
    2. Ne jamais attribuer les droits 777 : l'attribution d'un umask 000 ou d'un chmod 777 est une faille de sécurité majeure permettant à n'importe quel compte compromis de modifier ou corrompre vos fichiers.
    3. Auditer régulièrement les droits SUID/SGID : rechercher les binaires possédant des privilèges élevés pour prévenir les attaques par élévation de privilèges : 
      $ find / -perm /4000 -type f 2>/dev/null
