    8. II.1 Terminologie : shell, terminal, console et script shell

    8.1 II.1.1 Introduction

    Dans le vocabulaire courant, shell, terminal et console désignent souvent, par abus de langage, la même chose : une fenêtre dans laquelle on peut saisir et exécuter des commandes.

    Si l'on souhaite être plus rigoureux :

    • Shell : un interpréteur de commandes destiné aux systèmes d’exploitation de type Unix qui permet d’interagir avec le noyau et d'accéder aux fonctionnalités internes du système. Il se présente sous la forme d’une interface en ligne de commande (CLI - Command Line Interface) accessible depuis la console ou un émulateur de terminal.
    • Terminal : historiquement, un équipement physique de communication (clavier + écran) relié à un ordinateur central (mainframe). Aujourd'hui, il désigne couramment un émulateur de terminal (fenêtre logicielle) fournissant l'interface visuelle pour interagir avec un shell. Il fonctionne selon le principe REPL (Read-Eval-Print Loop) :
      • Read : l’utilisateur saisit une commande qui est lue par le shell,
      • Eval : cette commande est interprétée, exécutée et produit un résultat,
      • Print : la sortie de la commande est affichée à l’écran,
      • Loop : le système attend la commande suivante.
    • Console : historiquement, le terminal physique directement raccordé à l'unité centrale de l'ordinateur, réservé à l'administration du système. Sous Linux moderne, les consoles virtuelles (accessibles via Ctrl+Alt+F1 à F6) permettent d'accéder directement au système en mode texte sans serveur graphique.
    • Un script shell est un fichier texte contenant une séquence de commandes shell destinées à être exécutées de manière séquentielle ou automatisée.

    8.2 II.1.2 Les variantes shell

    Remarque

    Les commandes de base sont généralement les mêmes entre ces shells, mais certains shells peuvent offrir des fonctionnalités supplémentaires ou des syntaxes légèrement différentes.

    Le shell est l'interpréteur de commandes qui sert d'interface entre l'utilisateur et le noyau (kernel) du système d'exploitation. Il lit les commandes saisies au clavier, les interprète et les exécute. On distingue plusieurs familles de shells :

    • sh (Bourne Shell) : le shell historique d'Unix.
    • bash (Bourne-Again SHell) : l'évolution de sh, shell par défaut sur la majorité des distributions Linux actuelles.
    • zsh : un shell plus récent (1990) combinant les caractéristiques de plusieurs familles et offrant des fonctionnalités avancées (autocomplétion puissante, thèmes, structures de données complexes).

    Quand on travaille en mode ligne de commande, l'invite de commande affiche généralement le nom de l'utilisateur, le nom de la machine et le répertoire courant, suivi d'un symbole indiquant que le shell est prêt à recevoir une commande. Par exemple :

    frank@linux-course:~/Documents$

    La partie frank@linux-course indique que l'utilisateur frank est connecté à la machine linux-course. La partie ~/Documents indique que le répertoire courant est Documents, situé dans le répertoire personnel de l'utilisateur (le symbole ~ représente le répertoire personnel ou home directory).

    Le dernier symbole $ indique que l'utilisateur connecté est un utilisateur standard sans privilèges particuliers. Ce symbole devient # lorsque l'utilisateur est le super-utilisateur (root).

    8.3 II.1.3 Le shell Bash

    Bash (acronyme de Bourne-Again shell) est un interpréteur en ligne de commande de type script. C’est le shell officiel du projet GNU.

    Usage

    Comme tous les interpréteurs en ligne de commande de type script, Bash remplit quatre fonctions fondamentales :

    1. Il fournit un ensemble de commandes permettant d’opérer sur l’ordinateur (lancement de programmes, manipulation de fichiers, etc.) ;
    2. Il permet de regrouper ces commandes dans un fichier texte appelé script pour une exécution automatisée ;
    3. Il vérifie la syntaxe des commandes lors de leur exécution et renvoie un message explicite en cas d’erreur ;
    4. Il interprète chaque ligne de commande validée en la traduisant en appels système compréhensibles par le noyau Linux, qui se charge de son exécution.

    Fonctionnement

    Bash peut être utilisé selon deux modes :

    • Mode interactif : Bash attend les commandes saisies au clavier par l'utilisateur, renvoie immédiatement le résultat à l'écran, puis réaffiche l'invite de commande.
    • Mode batch (non interactif) : Bash lit et exécute séquentiellement les instructions contenues dans un fichier de commandes (communément appelé script Bash ou script shell).

    8.4 II.1.4 Entrées / sorties standard en shell

    Entrées

    La commande read permet d’effectuer une saisie utilisateur depuis l'entrée standard (stdin). La commande echo permet d’afficher une chaîne de caractères sur la sortie standard (stdout). Par exemple :

    $ read var      # Saisie de la valeur (depuis l'entrée standard stdin)
$ echo $var     # Affichage de la variable (remarquez le préfixe $ pour évaluer son contenu)

    Sorties standard et redirections

    Une commande affiche normalement son résultat sur la sortie standard stdout (l'écran). On peut rediriger ce résultat vers un fichier à l'aide des opérateurs de redirection :

    $ echo "Bonjour"                    # Envoie le texte sur la sortie standard (l'écran)
$ echo "Bonjour" > salut.txt        # Redirige la sortie vers salut.txt (crée le fichier ou écrase son contenu)
$ echo "Tout le monde" >> salut.txt # Ajoute la ligne à la fin du fichier sans en effacer le contenu (mode append)

    Sortie d'erreur standard (stderr)

    Les messages d'erreur ne transitent pas par la sortie standard : ils sont émis sur un canal dédié appelé flux de sortie d'erreur (stderr, descripteur de fichier 2).

    Par exemple, si le fichier toto n'existe pas dans le répertoire courant :

    $ cat toto
cat: toto: Aucun fichier ou dossier de ce type

    La commande produit un message d'erreur sur stderr. Si l'on souhaite masquer cette erreur :

    $ cat toto 2>/dev/null

    Ici, 2> redirige spécifiquement le flux d'erreur stderr vers le périphérique spécial /dev/null (le « trou noir » du système), ce qui empêche l'affichage du message d'erreur.

    8.5 II.1.5 Les filtres, tubes et redirections

    Les systèmes Unix fournissent de nombreux utilitaires spécialisés appelés filtres, par exemple :

    • grep : recherche et affiche les lignes correspondant à un motif (mot-clé ou expression régulière),
    • wc : compte les lignes (-l), les mots (-w) ou les caractères (-m),
    • sort : trie les lignes selon un ordre précis (alphabétique, numérique),
    • tail : affiche les dernières lignes d'un flux ou fichier,
    • head : affiche les premières lignes d'un flux ou fichier.

    Ces filtres prennent tout leur sens lorsqu'ils sont combinés à l'aide de tubes (pipes), représentés par le symbole |, qui connectent la sortie standard d'une commande à l'entrée standard de la suivante.

    Exemples :

    $ cat monfichier | wc -l

    Compte le nombre de lignes dans le fichier monfichier.

    $ cat monfichier | sort > fichiertrie

    Trie les lignes du fichier monfichier par ordre lexicographique, puis enregistre le résultat dans le fichier fichiertrie.

    8.6 II.1.6 Les scripts shell

    Les scripts shell sont des fichiers texte exécutables portant généralement l'extension .sh. Ils regroupent une suite ordonnée de commandes, enrichie de structures algorithmiques (variables, conditions, boucles). Ils sont indispensables en administration système pour automatiser les tâches répétitives (sauvegardes, déploiements, maintenance) et fiabiliser les procédures opérationnelles.
