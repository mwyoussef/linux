    9. II.2 Les variables d’environnement

    Les variables d'environnement sont des paires clé-valeur utilisées par le système d'exploitation et les applications pour stocker des informations de configuration et d'exécution. Elles jouent un rôle crucial dans le fonctionnement du shell et des programmes en fournissant des données sur l'environnement d'exécution, les chemins d'accès, les préférences linguistiques ou l'identité de l'utilisateur.

    Pour accéder au contenu d’une variable d’environnement, on utilise la syntaxe $NOM_VARIABLE. Par exemple, pour afficher le contenu de la variable HOME (qui contient le chemin absolu du répertoire personnel de l'utilisateur connecté) :

    $ echo $HOME
/home/frank

    La commande echo

    La commande echo affiche les arguments qui lui sont passés sur la sortie standard. Exemple : echo Hello affiche Hello. Pour afficher le contenu d'une variable, on la préfixe du caractère $ (opérateur d'évaluation ou d'expansion de variable) : echo $HOME.

    9.1 II.2.1 La variable PATH

    La variable d'environnement PATH est l'une des plus fondamentales du système. Elle contient la liste ordonnée des répertoires (séparés par le caractère deux-points :) dans lesquels le shell recherche les fichiers exécutables lorsqu'une commande est saisie.

    Lorsque vous tapez une commande comme ls, le shell parcourt successivement chaque répertoire listé dans PATH jusqu'à trouver le binaire exécutable correspondant.

    Pour afficher la valeur de PATH :

    $ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

    Dans cet exemple, le shell cherchera les commandes successivement dans /usr/local/sbin, puis /usr/local/bin, /usr/sbin, /usr/bin, /sbin, et enfin /bin. Dès qu'une correspondance est trouvée, le programme est exécuté. Si la commande n'est trouvée dans aucun de ces répertoires, le shell renvoie une erreur : command not found.

    Si un programme ou script exécutable ne se trouve pas dans un répertoire listé dans le PATH, vous devez obligatoirement préciser son chemin d'accès (par exemple ./mon_script.sh pour un fichier situé dans le répertoire courant).

    9.2 II.2.2 Autres variables d’environnement courantes

    Outre PATH, le système initialise de nombreuses variables d'environnement indispensables au comportement du shell et des applications :

    • HOME : chemin absolu du répertoire personnel de l'utilisateur (ex. /home/frank).
    • USER : nom de l'utilisateur actuellement connecté.
    • SHELL : chemin de l'interpréteur de commandes par défaut (ex. /bin/bash).
    • LANG : paramètres régionaux, encodage et langue du système (ex. fr_FR.UTF-8).
    • PWD : répertoire de travail actuel (Print Working Directory).
    • UID : identifiant numérique unique de l'utilisateur (ex. 1000 pour un utilisateur standard, 0 pour root).

    9.3 II.2.3 Manipulation des variables d’environnement

    Distinction essentielle : variable de shell vs variable d'environnement

    • Une variable de shell (locale) est créée par simple affectation (VAR=valeur). Elle n'existe que dans le shell courant et n'est pas transmise aux processus enfants (scripts lancés, sous-shells).
    • Une variable d'environnement est exportée via la commande export (export VAR ou export VAR=valeur). Elle est alors automatiquement héritée par tous les processus enfants créés à partir de ce shell.

    9.3.1 II.2.3.1 Afficher les variables d’environnement

    Pour lister l'ensemble des variables d'environnement de la session active, utilisez la commande env (ou printenv) :

    $ env
HOME=/home/frank
USER=frank
SHELL=/bin/bash
LANG=en_US.UTF-8
PWD=/home/frank
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

    9.3.2 II.2.3.2 Définir et exporter une variable

    Pour créer une variable d'environnement ou convertir une variable locale en variable d'environnement, on utilise la commande export :

    $ export MY_VAR="Bonjour le monde"

    Cette variable est désormais accessible à tous les programmes et scripts exécutés depuis ce shell.

    Pour modifier temporairement une variable existante (comme PATH) en lui ajoutant un nouveau répertoire :

    $ export PATH=$PATH:/home/frank/bin

    Cette commande ajoute /home/frank/bin à la fin de la variable PATH, permettant d'exécuter directement les programmes situés dans ce dossier sans préfixer leur chemin.

    9.3.3 II.2.3.3 Supprimer une variable

    Pour détruire une variable (qu'elle soit locale ou d'environnement) dans la session en cours, utilisez la commande interne unset :

    $ unset MY_VAR

    La variable MY_VAR cesse alors d'exister dans la session courante.

    9.4 II.2.4 Portée et persistance des variables

    Les variables définies dans un shell ne sont valables que pour la durée de vie de cette session. À la fermeture du terminal ou au redémarrage, elles sont perdues.

    Pour rendre une variable d'environnement permanente, il est nécessaire d'inscrire la commande export dans l'un des fichiers d'initialisation du shell lus automatiquement à la connexion :

    • ~/.bashrc : pour les shells interactifs sans connexion (ouverture d'un terminal graphique),
    • ~/.bash_profile ou ~/.profile : pour les sessions de connexion (login shell).
