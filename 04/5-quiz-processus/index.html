    28. IV.5 Questions d'auto-évaluation

    1. oneko est un programme amusant qui affiche un chat poursuivant le curseur de votre souris. S’il n’est pas déjà installé sur votre machine, installez-le avec votre gestionnaire de paquets (sudo apt install oneko). Nous allons l’utiliser pour manipuler le contrôle des tâches (job control).

      1.1 Lancez le programme. Quelle commande tapez-vous ?

      Réponse

      Installation si nécessaire : 

      $ sudo apt update
$ sudo apt install oneko

      Lancement en avant-plan : 

      $ oneko

      1.2 Déplacez le curseur de la souris pour observer le chat. Suspendez maintenant le processus. Quelle combinaison de touches utilisez-vous et quel est le message obtenu ?

      Réponse

      En appuyant sur la combinaison de touches Ctrl+Z :

      [1]+  Stopped                 oneko

      1.3 Vérifiez l'état des tâches de votre session shell courante. Quelle commande tapez-vous ?

      Réponse 
      $ jobs
[1]+  Stopped                 oneko

      1.4 Relancez maintenant cette tâche en arrière-plan en utilisant son numéro de tâche (job ID). Quelle commande utilisez-vous ? Comment constatez-vous qu'elle s'exécute à nouveau ?

      Réponse 
      $ bg %1
[1]+ oneko &

      Le curseur de commande réapparaît dans le terminal et le chat se remet immédiatement à courir après la souris.

      1.5 Terminez la tâche en spécifiant son identifiant de tâche (job ID). Quelle commande utilisez-vous ?

      Réponse 
      $ kill %1

    2. Identifiez les PID de tous les processus engendrés par le serveur web Apache HTTPD (apache2) à l’aide de deux commandes distinctes :

      Réponse

      Avec pgrep : 

      $ pgrep apache2
      Ou avec pidof : 
      $ pidof apache2

    3. Terminez tous les processus apache2 sans spécifier manuellement leurs PID, en utilisant deux commandes distinctes :

      Réponse

      Avec pkill : 

      $ pkill apache2
      Ou avec killall : 
      $ killall apache2

    4. Comment arrêter l'ensemble des processus apache2 en utilisant la commande kill avec son signal par défaut (SIGTERM) combinée en une seule ligne de commande ?

      Réponse

      En utilisant la substitution de commande : 

      $ kill $(pgrep apache2)
      Ou : 
      $ kill $(pidof apache2)

      Remarque : SIGTERM (15) étant le signal envoyé par défaut par kill, il n'est pas nécessaire de spécifier d'option de signal.

    5. Lancez top et réalisez les manipulations interactives suivantes :

      5.1 Afficher l'arborescence hiérarchique des processus :

      Réponse

      Lancer la commande top, puis appuyer sur la touche V.

      5.2 Afficher la ligne de commande complète des processus en distinguant l'espace utilisateur de l'espace noyau :

      Réponse

      Appuyer sur la touche c.

      5.3 Afficher avec ps tous les processus appartenant à l’utilisateur système du serveur Apache (www-data) :

      Réponse 
      $ ps -u www-data

    6. Le signal SIGHUP permet de recharger la configuration de nombreux démons sans interruption de service. Avec Apache HTTPD, l'envoi de SIGHUP au processus parent (démarré par root) termine proprement les processus enfants de traitement et en recrée de nouveaux avec la configuration mise à jour. Réalisez les étapes suivantes :

      6.1 Démarrez le serveur Apache :

      Réponse 
      $ sudo systemctl start apache2

      6.2 Repérez le PID du processus parent :

      Réponse 
      $ ps aux | grep apache2
root      2204  0.0  0.1   6572  5196 ?        Ss   06:50   0:01 /usr/sbin/apache2 -k start
www-data  3547  0.0  0.3 1211248 12168 ?       Sl   07:10   0:00 /usr/sbin/apache2 -k start
www-data  3548  0.0  0.2 1211248 8080 ?        Sl   07:10   0:00 /usr/sbin/apache2 -k start
wy        3895  0.0  0.0  76356  2092 pts/0    S+   12:58   0:00 grep apache2

      Le processus parent est celui exécuté par le superutilisateur root (ici PID 2204). Il possède deux processus enfants (PID 3547 et 3548).

      6.3 Demandez au serveur Apache de recharger sa configuration en envoyant le signal SIGHUP à son processus parent :

      Réponse 
      $ sudo kill -SIGHUP 2204

      6.4 Vérifiez que le processus parent est toujours actif et que de nouveaux processus enfants ont été instanciés :

      Réponse 
      $ ps aux | grep apache2
root      2204  0.0  0.1   6572  5200 ?        Ss   06:50   0:01 /usr/sbin/apache2 -k start
www-data  3900  0.0  0.1 1211248 6012 ?        Sl   13:00   0:00 /usr/sbin/apache2 -k start
www-data  3901  0.0  0.1 1211248 6012 ?        Sl   13:00   0:00 /usr/sbin/apache2 -k start
wy        3957  0.0  0.0  76356  2264 pts/0    S+   13:00   0:00 grep apache2

      Le processus parent (PID 2204) a conservé son PID, tandis que deux nouveaux processus enfants (3900 et 3901) ont pris le relais.

    7. Dans un système multitâche préemptif, que se produit-il lorsqu’un processus de faible priorité s'exécute sur le processeur et qu’un processus de priorité supérieure devient prêt à s'exécuter ?

      Réponse

      L'ordonnanceur interrompt (préempte) le processus de faible priorité pour allouer immédiatement le processeur au processus le plus prioritaire.

      Quel PID possède la priorité la plus élevée ?

      Réponse

      Le PID 12 avec une priorité PRI de -40 (processus temps réel).

    10. Vous tentez de modifier la priorité d’un processus avec renice et obtenez le message d'erreur suivant :

      $ renice -10 21704
renice: failed to set priority for 21704 (process ID): Permission denied

      Quelle est la cause de ce refus ?

      Réponse

      Seul le superutilisateur root (via sudo) a le droit d'attribuer une valeur nice négative pour rendre un processus plus prioritaire.

    11. Avec la commande ps en format long sous Linux, quelle option --sort permet de trier les processus par consommation CPU dans l'ordre croissant ?

      Réponse 

      $ ps -el --sort=pcpu
      (Pour un tri décroissant, on préfixerait le champ d'un tiret : --sort=-pcpu).
